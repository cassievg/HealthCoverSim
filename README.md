# Installation and Running the Project

## Frontend

To install the dependencies for the frontend of the project, navigate to the frontend folder and run `npm install`.
```
cd frontend
npm install
```

Then run the frontend using `npm run dev`.

## Backend

To install the dependencies for the backend of the project, navigate to the backend folder and run `npm install`.
```
cd backend
npm install
```

In a separate terminal from where the frontend is running, run `node server.js` to start the server.

Note that both the frontend and backend must be running in parallel for the app to work.

# Database Creation

Database was created using sqlite3 v6.0.1. The complete DB initialization can be viewed in `backend/db.js`.
There is only one table in the DB named 'quotes'.

Below lists the fields of the 'quotes' table.
- `id`: The unique ID that acts as the identifier for each quote. Automatically generated by the backend incrementally.
- `customer_name`: The name of the customer whose quote belongs to.
- `cover_type`: The cover type chosen by the customer. Values can be single, couple, or family.
- `applicant1_age`: The age of the first applicant.
- `applicant1_cover_history`: The cover history for the first applicant. Values can be yes, no, or not sure.
- `applicant2_age`: The age of the second applicant. Values can range between 18-100. This field is saved as null for single cover type due to the absence of a second applicant.
- `applicant2_cover_history`: The cover history for the second applicant. Values can range between 18-100. Values can be yes, no, or not sure. This field is saved as null for single cover type due to the absence of a second applicant.
- `hospital_cover`: The type of hospital cover owned by the customer. Values can be none, basic, bronze, silver, or gold.
- `extras_cover`: The type of extras cover owned by the customer. Values can be none, basic, standard, or premium.
- `payment_frequency`: The payment frequency chosen by the customer. Values can be monthly or yearly.
- `annual_discount`:  The annual discount rewarded to the customer. Values can range between 0-10.
- `notes`: Additional notes. This field is optional.
- `created_at`: The time and date at which the quote was created.

For `hospital_cover` and `extras_cover`, the corresponding costs of each cover level is not saved in the backend. Instead, it is saved as a converter in `/frontend/utils`.

# Pricing Rules

Quoted from the assessment instructions, below are the pricing rules that were applied in the calculations.

Hospital cover:
- none: $0
- basic: $90
- bronze: $120
- silver: $160
- gold: $220

Extras cover:
- none: $0
- basic: $25
- standard: $45
- premium: $70

Cover type:
- single: 1 adult
- couple: 2 adults
- family: 2 adults + $30/month upgrade fee

# Calculation Logic

Below lists the steps, formula, and rules used for each calculation step until the final estimate of the yearly premium.

### Applicant Premiums
These are calculated separately per applicant. This includes the LHC loading whose value is determined by the applicant's age and cover history. This amount is only applied to the hospital cover and does not include the extras cover.

The LHC amount is calculated as such:
1. If the applicant's cover history is no and the applicant's age is above 30, the LHC % is calculated as `(age - 30) * 2`. Otherwise, the LHC % is 0.
2. The chosen hospital cover cost is multiplied by this percentage to obtain the LHC loading amount for this applicant.
3. The LHC loading amount is added into the hospital cover cost to obtain the monthly premium for this applicant.
4. If there is applicant 2, calculate the LHC and monthly premium using the same steps.

### Hospital Total
The hospital total is simply the total of the monthly premiums obtained in the applicant premiums.

### Extras Total
Extras are calculated according to the the number of adults. In the case where the cover type is single and the number of applicants is 1, multiply the extras cover cost by 1. Otherwise, in the case where the cover type is single or couple and the number of applicants is 2, multiply the extras cover cost by 2.

### Family Upgrade Fee
The family upgrade fee is applied only when the cover type is family. An extras $30 is added into the monthly premium.

### Monthly Premium
The monthly premium is the summation of the hospital total, extras total, and the family upgrade fee if any. 

### Yearly Premium
The raw yearly premium is obtained by multiplying the monthly premium by 12. Annual discounts are applied with the following rules:
1. Discounts are manually granted in the quote creation. In the case where the quote has payment frequency 'monthly', the annual discount will always be 0.
2. Discounts can only range from 0 to 10%.

The final estimate of the yearly premium will be obtained in this stage.

# Limitations of the Web App

Below lists the limitations of the current Health Cover Sim app:
- Does not support mobile access. This is due to the unfit resizing of the 'Quotes List' page.
- Premiums and calculations are not accurate to real life health insurance systems.
